# 灵动岛展开与收起修复记录

日期：2026-10-29

已读取项目 PRD.md、DESIGN.md，检查 lib/index.js、lib/registry.js 和 helper/island-helper.swift。本次围绕用户明确反馈的“点击绿点展开后，点击岛外无法收回”完成修复。

## 根因与修复

- 原 onModeChange 在创建控制器之前使用 `[weak controller]`，永久捕获 nil；状态切换没有执行窗口布局回调。回调改为在控制器初始化后捕获自身。
- 全屏透明捕获窗口没有正确设置层级，还会遮挡正常窗口。移除捕获窗口，使用 AppKit 的全局与本地鼠标事件监听。
- 固定动画画布大于实际岛体；现在渲染与点击命中共用尺寸及圆角边界。鼠标位于透明区域时启用 ignoresMouseEvents，让同一次点击继续交给原窗口。
- 原逻辑每次收到含 pending 的状态都会展开。现在按 requestId 识别新交互；手动收起后，同一请求的状态刷新保持收起，下一个新审批仍会展开。
- 顶部收起区域原来混用了窗口底部起算的 y 坐标；改用屏幕顶部边界计算。
- stdin 关闭、shutdown 帧到达时主动退出，减少辅助进程残留。监听器、延迟隐藏任务和完成提示计时器按生命周期清理。
- 展开内容按普通行和审批行分别分配高度；列表超出屏幕时滚动。绿点增加原生按钮与无障碍标签。提问卡使用“查看问题”，避免将提问误当作工具权限发送 allowed-once/rejected。

## 验证

运行：`node --test tests/run-tests.mjs`。脚本会从当前源码编译 helper，无需第三方依赖；需要 macOS 与 Xcode Command Line Tools。

- 17 条 Swift 断言通过：手动展开/收起、同一审批刷新不重开、新审批展开、审批结束收回、空闲收回、透明区域与圆角命中、列表高度、正文前缀。
- 3 条进程协议测试通过：stdin EOF 退出、分块 shutdown 正常退出、无效 JSON 后继续处理。
- 原生测试面板验证：测试审批按钮正常响应；审批结束收回绿点；点击可访问的绿点按钮展开两个任务。
- 用户在测试面板上用真实鼠标点击岛外，明确确认“会收起”。无障碍控件调用不产生真实鼠标事件，因此单独核验了这一项。
- 正式部署后，二进制与测试产物逐字节一致，源码哈希与缓存一致；桥接主进程未重启，正式 helper 已由原桥接自动拉起。
